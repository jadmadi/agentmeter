## Runbook (verified 2026-10-26)

The Go CLI is the supported runtime. Python is the reference/oracle only.

Build the binary:

```bash
go build -trimpath -o bin/agentmeter ./cmd/agentmeter
# or the release path:
./build.sh --release --no-install
# all six release artifacts + version.json + checksums.txt:
./build.sh --all
```

Run either report:

```bash
bin/agentmeter cmd --serve
bin/agentmeter cmd --watch
bin/agentmeter oc --serve
bin/agentmeter oc --watch
```

Compare the two tools (a report directory/file or a live store/root on each
side):

```bash
bin/agentmeter compare
bin/agentmeter compare oc-cmd
bin/agentmeter compare data/oc data/cmd --serve
bin/agentmeter compare --oc data/oc --cmd data/cmd --serve
bin/agentmeter compare --oc <db|report> --cmd <root|report> --watch
```

`--serve` is a build-once static server; `--watch` rebuilds when the source
changes while serving.

Go verification:

```bash
gofmt -l .
go vet ./...
go test ./...
```

Python oracle (contributors only):

```bash
python3 -m pip install -r requirements-dev.txt
python3 -m pytest
python3 command-code-telemetry/py/audit.py --root <tree> --data <report>
python3 opencode-telemetry/py/audit.py --db <store> --data <report>
```

Full correctness gate (Go build/tests + Python oracle + fixture audit):

```bash
./check.sh
```

The Go builders enforce schema v3 and fail closed on any contract invariant.
See `CONTRACT.md` for field definitions, censoring, attribution, and spend.

Run the quality gate before commits:

```bash
sila gate
```

# AGENTS.md — telemetry

## 0. Safety Rails (NEVER Do This)
- No unprompted remote push: Local commits are autonomous; remote push requires user consent.
- No unauthorized repo creation or re-homing: NEVER run 'gh repo create' or push external specs to personal namespaces; fail closed on auth hurdles.

## 1. Working Relationship & Discipline
- Concise and direct.
- Terminal Markdown: Keep visible line and table width under 80 chars; no hard breaks inside bullets or links.
- Decision Brief & `/adoo` Receipts: Lead with 1-line verdict ("X happens because Y, confirmed by Z"), compact receipt/risk table, file links, and next action. No 1-5 scores.
- Verified Repo Runbook Primacy: Never guess commands; verify exit code 0 locally.
- Closed-Loop Goal Attribution (6 Steps) for `goals/<slug>/`:
  1. Check every completed task `- [x]` in `goals/<slug>/plan.md`.
  2. Write markdown evidence with a standalone `Verdict: PASS` line.
  3. Commit with `(goals/<slug>/goal.md)` or `[goal: <slug>]` under `feat:`, `fix:`, `refactor:`, `perf:`, or `chore:` (`docs:`/`test:` ignored).
  4. Certify via `sila goals certify <slug> --evidence=goals/<slug>/evidence.md` or `sila goals audit <slug>`.
  5. Run `sila goals` to reconcile `goals/README.md` and commit receipts.
  6. Verify `sila goals --json` reports `status: "implemented"`, `verification_status: "verified"`, `unverified_count: 0`, and clean `git status`.
