What was actually measured

Every assistant message in a Command Code session stores its own token usage. By pairing each reply with the entry that triggered it, we can recover wall-clock time per model step — no stopwatch, no benchmark harness.

Method · how a step is timed

A step is one assistant message. Duration runs from the moment its parent entry commits (your message, or the previous tool result) until the reply commits. That includes TTFT, prefill, queueing and generation, and excludes the tool execution itself. Each step also stores cache-read/write tokens, recorded cost, effort, content block types (thinking vs tool call), tool names, and the session's working directory. Counts in this panel cover the full history; the charts and tables below follow the filters.

Two numbers, often confused
Effective rate
total output tokens ÷ full step time
Decode rate
marginal tokens ÷ added generation time
Fixed overhead
≈8s on a final answer, ≈14s on a tool turn
Short-step penalty
the smaller the output, the worse the effective rate

The median final-answer rate is an effective rate for a typical answer. The model's marginal decode rate is higher — you only see it when a response is long enough to amortise the fixed cost. Every chart below responds to the filters above.

Reproduce it

The Go fetcher only reads session JSONL files; it never emits prompts, code, or message text. Aggregates and compact per-step rows land in data/cmd/.

# from this directory
agentmeter cmd

# or build, serve and open the report
agentmeter cmd --serve

# optional filters
agentmeter cmd --models model-a,model-b --since 2026-09-01 --until 2026-10-22
Live single-request check, for comparison with the historical numbers above (replace <model-id> with a model from the table):
cmd -p 'Write a 600-word plain-text essay about the history of tea. Do not use tools.' \
  -m <model-id> --output-format json |
jq -r 'select(.type=="result") | .usage.outputTokens as $o | .durationMs as $d
       | "\($o) tok in \($d/1000)s = \($o/($d/1000) | floor) tok/s"'

Timestamps are commit times from the append-only session log, so each duration includes client-side receipt and any provider queueing. Generated/output tokens include reasoning tokens. inputTokens is the canonical total input; freshInputTokens and inputRawTokens are separate. costUsd covers successful rows and totalSpendUsd adds skipped/error rows. Pricing varies by model and era, so cross-model $/1M gen is not always like-for-like. ratio is a fraction (ratioPct is percent) and index is the normalized pace. Valid-rate extremes and invalid timestamp artifacts are reported separately. Forked sessions reuse message ids; those copies are skipped and counted as duplicate spend. No prompts, assistant text, tool arguments or file contents are read or emitted. This is an observational analysis of one machine's history, not a controlled benchmark.
